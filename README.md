# ওষুধঘর (OshudGhor) — Multi-Branch Pharmacy Management

একটা সম্পূর্ণ, স্বাধীন React app + real cloud database (Supabase)। এতে থাকছে:
- সব শাখা/ডিভাইস থেকে **লাইভ সিঙ্ক** (এক জায়গায় বিক্রি করলে বাকি সব জায়গায় সাথে সাথে স্টক আপডেট)
- **আসল লগইন** (email + password, প্রতিটা স্টাফের নিজস্ব অ্যাকাউন্ট)
- **রোল-ভিত্তিক অ্যাক্সেস কন্ট্রোল যেটা সার্ভার-লেভেলে বাস্তবে enforce করা** (Row Level Security) — স্টাফ role UI থেকে হাইড করা তো বটেই, ডেভেলপার টুল দিয়ে সরাসরি API কল করলেও customer/financial ডেটা পড়তে/বদলাতে পারবে না।

---

## ধাপ ১ — Supabase প্রজেক্ট বানান (ফ্রি, ৫ মিনিট)

1. [supabase.com](https://supabase.com) এ গিয়ে সাইন আপ করুন (কোনো ক্রেডিট কার্ড লাগবে না)।
2. "New Project" — একটা নাম দিন (যেমন `oshudghor`), একটা ডাটাবেজ পাসওয়ার্ড সেট করুন (মনে রাখুন), region হিসেবে Singapore বেছে নিন (বাংলাদেশ থেকে সবচেয়ে কাছের)।
3. প্রজেক্ট তৈরি হতে ~২ মিনিট লাগবে।

## ধাপ ২ — ডাটাবেজ স্কিমা রান করুন

1. বাম পাশের মেনু থেকে **SQL Editor** এ যান → **New query**।
2. এই প্রজেক্টের `supabase/schema.sql` ফাইলের **সম্পূর্ণ কনটেন্ট** কপি করে পেস্ট করুন।
3. **Run** চাপুন। ("Success. No rows returned" দেখালে ঠিক আছে।)

এটা সব টেবিল (loyalty points সহ), Row Level Security পলিসি, এবং `record_sale()` ফাংশন (যেটা POS বিক্রয় ও পয়েন্ট নিরাপদে হ্যান্ডেল করে) তৈরি করে দেবে — একটা ফাইলেই সবকিছু, আলাদা কিছু রান করার দরকার নেই।

**আগে থেকে প্রজেক্ট চালু থাকলেও** এই ফাইলটা আবার সম্পূর্ণ কপি-পেস্ট করে Run করুন — এটা নিরাপদ (কোনো ডেটা মুছবে না), এবং একটা গুরুত্বপূর্ণ ফিক্স যোগ করে: আগে কোনো শাখা ডিলিট করলে তার পুরনো বিক্রয়/মেডিসিন ডেটা "ভুতুড়ে" হয়ে ড্যাশবোর্ডের হিসাবে থেকে যেত (যেহেতু ডিলিট cascade করত না) — এখন থেকে branch ডিলিট করলে তার সব ডেটা ঠিকমতো পরিষ্কার হবে।

## ধাপ ৩ — API keys কপি করুন

1. বাম মেনুতে **Project Settings → API** এ যান।
2. **Project URL** এবং **anon public** key — এই দুটো কপি করুন।

## ধাপ ৪ — App-এ keys বসান

1. এই ফোল্ডারে `.env.example` ফাইলটা `.env` নামে কপি/রিনেম করুন।
2. `.env` ফাইলে দুটো জায়গায় আপনার URL ও key বসান:
   ```
   VITE_SUPABASE_URL=https://xxxxxxxx.supabase.co
   VITE_SUPABASE_ANON_KEY=eyJhbGc...(আপনার আসল key বসবে এখানে)
   ```
3. সেভ করুন।

## ধাপ ৫ — Build ও Deploy

```bash
npm install
npm run build      # নতুন dist/ ফোল্ডার বানাবে (keys সহ)
```

`dist/` ফোল্ডারের ভেতরের সব ফাইল যেকোনো static hosting-এ আপলোড করুন:
- **Netlify:** netlify.com → সাইন আপ → "Deploy manually" → `dist` ফোল্ডার drag-drop
- **Vercel / Cloudflare Pages:** একই রকম drag-drop
- **cPanel:** `public_html`-এ `dist`-এর কনটেন্ট আপলোড

⚠️ **`.env` ফাইলে থাকা key `dist`-এর মধ্যে বেক হয়ে যায়** — এটা স্বাভাবিক, কারণ Supabase-এর "anon public" key পাবলিক হওয়ার জন্যই ডিজাইন করা (আসল নিরাপত্তা RLS পলিসি দিয়ে, key গোপন রাখা দিয়ে না)।

## ধাপ ৬ — প্রথম অ্যাকাউন্ট বানান

1. আপলোড করা লিংক খুলুন → "নতুন অ্যাকাউন্ট তৈরি করুন" থেকে সাইন-আপ করুন।
2. **এই প্রথম অ্যাকাউন্টটাই স্বয়ংক্রিয়ভাবে Admin হয়ে যাবে।**
3. Admin হিসেবে ঢুকে প্রথমেই **শাখা** পেজ থেকে আপনার শাখাগুলো যোগ করুন, **ইনভেন্টরি**-তে মেডিসিন যোগ করুন।
4. স্টাফদের app-এর লিংক দিন — তারা নিজে সাইন-আপ করলে ডিফল্টভাবে **স্টাফ** রোল পাবে। **এক্সেস কন্ট্রোল** পেজ থেকে তাদের রোল বদলে দিন (Manager করতে চাইলে)।

## রোল অনুযায়ী কে কী করতে পারবে

| | Admin | Manager | Staff |
|---|---|---|---|
| বিক্রয় (POS) | ✅ | ✅ | ✅ |
| বারকোড লুকআপ | ✅ | ✅ | ✅ |
| ইনভেন্টরি/শাখা/ক্রয়/কাস্টমার/রিপোর্ট | ✅ | ✅ | ❌ |
| স্টাফ-স্যালারি, ব্যাকআপ/রিস্টোর | ✅ | ❌ | ❌ |
| রোল/টিম ম্যানেজমেন্ট | ✅ | ❌ | ❌ |

এটা শুধু UI-তে পেজ লুকানো না — **Supabase Row Level Security** দিয়ে ডাটাবেজ-লেভেলে বাস্তবিকভাবে বন্ধ করা। স্টাফ অ্যাকাউন্ট দিয়ে ডেভেলপার টুল থেকে সরাসরি API কল করলেও customer/financial ডেটা পড়া বা বদলানো সম্ভব না।

### প্রতিটা মানুষের জন্য আলাদা করে পেজ বেছে দেওয়া

উপরের টেবিলটা প্রতিটা রোলের **সর্বোচ্চ সীমা** — কিন্তু একই রোলের দুইজনকে ভিন্ন ভিন্ন পেজ access দিতে চাইলে সেটাও করা যায়। **এক্সেস কন্ট্রোল** পেজে প্রতিটা ম্যানেজার/স্টাফের পাশে **"পেজ অ্যাক্সেস"** বাটনে চাপলে তার রোলের আওতার সব পেজের চেকবক্স দেখাবে — যেগুলো টিক দেবেন শুধু সেগুলোই সে দেখতে পারবে। যেমন:

- **ক্যাশ কাউন্টার ১** কে শুধু "বিক্রয়/POS" দিলেন
- **ক্যাশ কাউন্টার ২** কে "বিক্রয়/POS" + "সেলস রিটার্ন" দুটোই দিলেন
- **ম্যানেজার A** কে ইনভেন্টরি+ক্রয় দিলেন, কিন্তু কাস্টমার-বাকি/সাপ্লায়ার বাদ রাখলেন

"ডিফল্ট (সব) এ ফিরুন" চাপলে আবার সেই রোলের সবগুলো পেজ ফিরে আসবে। নতুন কেউ সাইন-আপ করলে ডিফল্টভাবে তাদের রোলের সব পেজই খোলা থাকে (custom না করলে)।

## লয়ালটি পয়েন্ট সিস্টেম

- POS-এ বিক্রির সময় কাস্টমারের **ফোন নম্বরই তার আসল identity** — একই নম্বর দিলে সিস্টেম যেকোনো শাখা থেকে চিনে ফেলবে এবং পুরনো পয়েন্ট দেখাবে। ফোন নম্বর না দিলে পয়েন্ট ট্র্যাক হবে না (ওয়াক-ইন সেল)।
- **একটাই রেশিও** (যেমন "১০০ টাকা = ১ পয়েন্ট") — অর্জন ও রিডিম দুটোতেই একই রেশিও ব্যবহার হয়, অর্থাৎ ১ পয়েন্ট ভাঙালে সমমূল্যের টাকা ছাড় পাওয়া যাবে।
- **পয়েন্ট অর্জন:** ফোন নম্বর দিয়ে বিক্রি করলে স্বয়ংক্রিয়ভাবে পয়েন্ট যোগ হয়।
- **পয়েন্ট রিডিম:** কাস্টমারের যথেষ্ট পয়েন্ট থাকলে POS-এ পয়েন্ট সংখ্যা লিখে "রিডিম করুন" চাপলে **Yes/No কনফার্মেশন** আসবে, নিশ্চিত করলেই ছাড় বিলে যোগ হয়ে যাবে। যথেষ্ট পয়েন্ট না থাকলে বা ফোন নম্বর না মিললে ডাটাবেজ নিজে থেকেই রিডিম আটকে দেবে।
- **যেদিন রিডিম করা হয়, সেদিনের বিক্রিতে নতুন কোনো পয়েন্ট যোগ হয় না** — এটা ডাটাবেজ ফাংশনে (`record_sale`) সরাসরি enforce করা, UI-এর ভুলের উপর নির্ভর করে না।
- **রেশিও বদলানো:** শুধু **Admin** — এক্সেস কন্ট্রোল পেজ থেকে বদলাতে পারবেন। Manager/Staff এই সেটিংস দেখতেও/বদলাতেও পারবে না — Supabase RLS দিয়ে ডাটাবেজ-লেভেলে বন্ধ, শুধু UI hide না।

## হেড অফিস / মেইন ডিপো ও স্টক রিকোয়েস্ট

- **শাখা** পেজে কোনো একটা শাখাকে "হেড অফিস / মেইন ডিপো" হিসেবে টিক দিন (একসাথে একটাই হেড অফিস থাকতে পারে)।
- এরপর **স্টক রিকোয়েস্ট** পেজ থেকে যেকোনো আউটলেট হেড অফিসের স্টক থেকে মাল চেয়ে রিকোয়েস্ট পাঠাতে পারবে।
- হেড অফিস (Admin/Manager) **অনুমোদন না করা পর্যন্ত স্টক সরে না** — অনুমোদন করলেই স্বয়ংক্রিয়ভাবে ট্রান্সফার হয়ে যায় এবং সেটা "স্টক ট্রান্সফার" পেজের হিস্টোরিতেও দেখা যাবে। এভাবে সব প্রোডাক্ট মুভমেন্ট হেড অফিসের নিয়ন্ত্রণে থাকে।
- হেড অফিস সেট না থাকলে পুরনো "স্টক ট্রান্সফার" পেজ দিয়ে সরাসরি (অনুমোদন ছাড়া) ট্রান্সফার করা যাবে, যেমন আগে ছিল।

## শাখা-ভিত্তিক থিম কালার

প্রতিটা শাখা এডিট করার সময় একটা কালার বেছে দিতে পারবেন। টপ বারে সেই নির্দিষ্ট শাখা সিলেক্ট করলে পুরো app-এর accent color সেই শাখার কালারে বদলে যাবে — "সব শাখা" বা কালার-না-দেওয়া শাখায় ডিফল্ট রঙে ফিরে আসবে। (ব্যাকগ্রাউন্ড ছবি/ওয়ালপেপার আপলোড এখনো নেই — সেটার জন্য আলাদা ফাইল-স্টোরেজ সেটআপ লাগবে, দরকার হলে জানাবেন।)

## কাস্টম তালিকা (পেমেন্ট মোড, ক্যাটাগরি, ডোজেজ ফর্ম, খরচের ক্যাটাগরি)

এই ড্রপডাউনগুলোতে এখন প্রি-সেট অপশনের পাশাপাশি **নিজের মতো টাইপ করেও নতুন অপশন যোগ করা যায়** — একবার ব্যবহার করলে সেটা পরের বার থেকে সাজেশনেও দেখাবে। নতুন কোনো পেমেন্ট গেটওয়ে বাজারে এলে POS-এর পেমেন্ট মোড বক্সে নাম টাইপ করলেই যোগ হয়ে যাবে, আলাদা কোনো সেটিংস পেজে যেতে হবে না।

## বারকোড স্ক্যান — ফোনের ক্যামেরা বা USB স্ক্যানার দুটোই চলবে

- **USB/Bluetooth স্ক্যানার:** কোনো সেটআপ লাগবে না — বারকোড ফিল্ডে ক্লিক করে স্ক্যান করলেই এমনিতে লেখা বসে যায় (স্ক্যানার আসলে কীবোর্ডের মতো কাজ করে)।
- **ফোনের ক্যামেরা:** ইনভেন্টরি ফর্ম, বারকোড লুকআপ, এবং POS — তিন জায়গাতেই "📷 ক্যামেরা দিয়ে স্ক্যান" বাটন আছে। এটা ব্রাউজারের নিজস্ব BarcodeDetector প্রযুক্তি ব্যবহার করে (Chrome/Edge Android-এ ভালো কাজ করে; পুরনো/iOS Safari-তে সাপোর্ট নাও থাকতে পারে, তখন ম্যানুয়াল/USB ব্যবহার করবেন)।
- POS-এ বারকোড স্ক্যান করলে মেডিসিন **সরাসরি কার্টে যোগ** হয়ে যায় — ড্রপডাউন থেকে খোঁজার দরকার নেই।

## ইনভয়েস প্রিন্ট ও কাস্টম নোট

- বিক্রয় সম্পন্ন হওয়ার সাথে সাথেই এখন প্রিন্ট প্রিভিউ **automatically খুলে যায়** — আলাদা করে খুঁজতে হবে না। পরে আবার দেখতে চাইলে "সাম্প্রতিক ইনভয়েস" তালিকায় প্রতিটা ইনভয়েসের পাশে "প্রিন্ট" বাটন আছে।
- **এক্সেস কন্ট্রোল** পেজে "ইনভয়েসে কাস্টম নোট/বিজ্ঞাপন" সেকশনে নিজের মতো লেখা (অফার, নির্দেশনা, শর্তাবলী) সেট করে দিতে পারবেন — সেটা প্রতিটা প্রিন্ট করা রিসিটের নিচে দেখাবে।

## ডেটা রিসেট (টেস্টিং শেষে ফ্রেশ শুরুর জন্য)

**এক্সেস কন্ট্রোল** পেজের একদম নিচে "ডেঞ্জার জোন" সেকশনে পুরো ডেটাবেজ (সব শাখা, মেডিসিন, বিক্রয়, কাস্টমার ইত্যাদি — টিম লগইন বাদে) মুছে ফেলার অপশন আছে। "DELETE" টাইপ করে কনফার্ম করলেই কাজ হয় — টেস্ট ডেটা মুছে বাস্তব ব্যবসার জন্য ফ্রেশ শুরু করতে এটা ব্যবহার করুন।

## অফলাইন বিক্রয় (WiFi চলে গেলেও বিক্রি বন্ধ হবে না)

- ইন্টারনেট চলে গেলে POS বিক্রি **আটকাবে না** — ইনভয়েসটা সেই ফোনেই সাময়িকভাবে সেভ থাকবে, টপ বারে "⚠️ অফলাইন" ও "N সিঙ্কের অপেক্ষায়" ব্যাজ দেখাবে।
- ইন্টারনেট ফিরলেই **স্বয়ংক্রিয়ভাবে** সার্ভারে সিঙ্ক হয়ে যায় — কোনো বাটন চাপতে হয় না।
- অফলাইনে থাকা অবস্থায় স্টক লোকালি (সেই ফোনেই) কমে দেখাবে, কিন্তু সার্ভারের real stock-এর সাথে মিলে যাবে সিঙ্কের পরই।
- **সীমাবদ্ধতা:** অফলাইনে একাধিক ডিভাইস থেকে একই কম-স্টক আইটেম বিক্রি হলে সামান্য oversell হতে পারে (সিঙ্কের সময় ধরা পড়বে, ম্যানুয়ালি ঠিক করতে হবে)। পয়েন্ট রিডিম করা সেলও অফলাইনে queue হয়, কিন্তু সিঙ্কের সময় যদি ততক্ষণে পয়েন্ট অন্য ডিভাইস থেকে খরচ হয়ে যায়, সেই একটা সেল সিঙ্ক ব্যর্থ হয়ে queue-তে থেকে যাবে (browser console-এ error লগ হয়) — Admin/Manager কে ম্যানুয়ালি চেক করে নিতে হবে।
- এটা browser-এর নিজের storage-এ থাকে, তাই **একই ডিভাইস/ব্রাউজারে পরে এসে** সিঙ্ক করতে হবে — ব্রাউজার ডেটা/ক্যাশ মুছে ফেললে বা অন্য ফোনে চলে গেলে সেই pending sale হারিয়ে যাবে (তাই খুব বেশিক্ষণ অফলাইন থাকলে সিঙ্ক না হওয়া পর্যন্ত সেই ফোনের ব্রাউজার ডেটা ক্লিয়ার করবেন না)।

## জানা সীমাবদ্ধতা

- রিপোর্ট/ড্যাশবোর্ড সাম্প্রতিক ৫০০টা ইনভয়েস নিয়ে হিসাব করে (পারফরম্যান্সের জন্য) — অনেক পুরনো ডেটা বিশ্লেষণ করতে চাইলে Supabase Dashboard থেকে সরাসরি SQL দিয়ে দেখতে হবে।
- Invoice নম্বর ক্লায়েন্ট-সাইডে (তারিখ+random) তৈরি হয় — দুটো ডিভাইস একই সেকেন্ডে বিল করলে (অত্যন্ত বিরল) নম্বর মিলে যাওয়ার ক্ষীণ সম্ভাবনা আছে, কিন্তু ডেটা হারায় না, শুধু invoice number.
- Supabase ফ্রি প্ল্যানে ৫০০MB ডাটাবেজ + সীমিত bandwidth — ছোট-মাঝারি ফার্মেসির জন্য যথেষ্ট, অনেক বড় হলে paid প্ল্যান লাগতে পারে।
